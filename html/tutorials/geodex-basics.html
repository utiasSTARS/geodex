geodex Basics#

In this tutorial, we create manifolds, measure tangent vectors, move along the manifold with the exponential and logarithmic maps, measure distances, interpolate along geodesics, sample random points, and then change the metric and the retraction of a manifold. Every step prints a value you can check by hand.

The full script is examples/tutorials/geodex_basics.py, and the C++ version is examples/tutorials/geodex_basics.cpp. The Python snippets import NumPy next to geodex, and the C++ snippets include the umbrella header.

import geodex
import numpy as np

Full example: examples/tutorials/geodex_basics.py

#include <iostream>

#include <geodex/geodex.hpp>

Full example: examples/tutorials/geodex_basics.cpp

See Riemannian Geometry for the terms this tutorial uses (manifold, tangent space, metric, exponential map, geodesic).

1. Create a manifold#

The 2-sphere \(\mathbb{S}^2\) is the set of unit vectors in \(\mathbb{R}^3\). In Python, geodex.Sphere() is the 2-sphere and geodex.SphereN(n) the \(n\)-sphere. In C++, the class template Sphere<Dim> models \(\mathbb{S}^n\), and Sphere<> is Sphere<2>.

sphere = geodex.Sphere()
print("dim =", sphere.dim())  # 2

Full example: examples/tutorials/geodex_basics.py

geodex::Sphere<> sphere;
std::cout << "dim = " << sphere.dim() << "\n";  // 2

Full example: examples/tutorials/geodex_basics.cpp

It prints dim = 2. Other manifolds follow the same pattern.

euclidean = geodex.Euclidean(3)  # R^3 with the standard metric
torus = geodex.Torus(2)          # 2-torus with the flat metric

Full example: examples/tutorials/geodex_basics.py

geodex::Euclidean<3> euclidean;  // R^3 with the standard metric
geodex::Torus<2> torus;          // 2-torus with the flat metric

Full example: examples/tutorials/geodex_basics.cpp

Every manifold is built from policies, a metric (what “length” means), a retraction (how to move along the manifold) and a sampler (how to sample points). The defaults are the round metric, the exponential map and a scrambled Halton sampler. In C++, they are template parameters, and Sphere<> is the same type as the fully qualified one below.

geodex::Sphere<2, geodex::SphereRoundMetric, geodex::SphereExponentialMap,
               geodex::ScrambledHaltonSampler>
    sphere;

Full example: examples/tutorials/geodex_basics.cpp

geodex provides these manifolds, each with its canonical metric by default (the round metric on spheres, the flat metric on tori, the bi-invariant metric on the rotation groups and a left-invariant metric on the rigid-body groups).

2. Measure tangent vectors#

A tangent vector at a point \(p\) is a velocity through \(p\). The metric gives two tangent vectors an inner product \(\langle u, v \rangle_p\) and a tangent vector a norm \(\|v\|_p\). Both functions take the base point first. On the sphere with the round metric, the inner product is the dot product of the ambient vectors.

sphere = geodex.Sphere()

p = np.array([0.0, 0.0, 1.0])  # north pole
u = np.array([1.0, 0.0, 0.0])  # tangent vector pointing east
v = np.array([0.0, 1.0, 0.0])  # tangent vector pointing south

ip = sphere.inner(p, u, v)
print("ip =", ip)  # 0.0 (orthogonal)
n = sphere.norm(p, u)
print("n =", n)  # 1.0

Full example: examples/tutorials/geodex_basics.py

geodex::Sphere<> sphere;

Eigen::Vector3d p{0.0, 0.0, 1.0};  // north pole
Eigen::Vector3d u{1.0, 0.0, 0.0};  // tangent vector pointing east
Eigen::Vector3d v{0.0, 1.0, 0.0};  // tangent vector pointing south

double ip = sphere.inner(p, u, v);
std::cout << "ip = " << ip << "\n";  // 0.0 (orthogonal)
double n = sphere.norm(p, u);
std::cout << "n = " << n << "\n";  // 1.0

Full example: examples/tutorials/geodex_basics.cpp

It prints ip = 0.0 and n = 1.0. At the north pole, the two vectors are orthogonal and of unit length. Euclidean space gives the same numbers for the same vectors.

print("n =", n)  # 1.0

Full example: examples/tutorials/geodex_basics.cpp

On a manifold with a position-dependent metric, such as the kinetic-energy metric of a robot arm, the same two vectors give a different inner product at every point.

3. Move with exp and log#

The exponential map \(\exp_p(v)\) starts at \(p\) and follows the geodesic in the direction of \(v\) for a length \(\|v\|_p\). The logarithmic map \(\log_p(q)\) is its inverse, the tangent vector at \(p\) that reaches \(q\).

sphere = geodex.Sphere()

p = np.array([0.0, 0.0, 1.0])  # north pole
q = np.array([1.0, 0.0, 0.0])  # point on the equator

# log gives the tangent vector at p that points toward q.
v = sphere.log(p, q)
print("v =", v)  # about [pi/2, 0, 0], along the great circle to the equator

# exp follows that tangent vector and recovers q.
q_recovered = sphere.exp(p, v)
print("q_recovered =", q_recovered)  # about [1, 0, 0]

Full example: examples/tutorials/geodex_basics.py

geodex::Sphere<> sphere;

Eigen::Vector3d p{0.0, 0.0, 1.0};  // north pole
Eigen::Vector3d q{1.0, 0.0, 0.0};  // point on the equator
Eigen::IOFormat fmt(4, Eigen::DontAlignCols, ", ", ", ", "", "", "[", "]");

// log gives the tangent vector at p that points toward q.
Eigen::Vector3d v = sphere.log(p, q);
std::cout << "v = " << v.transpose().format(fmt) << "\n";  // about [pi/2, 0, 0]

// exp follows that tangent vector and recovers q.
Eigen::Vector3d q_recovered = sphere.exp(p, v);
std::cout << "q_recovered = " << q_recovered.transpose().format(fmt)
          << "\n";  // about [1, 0, 0]

Full example: examples/tutorials/geodex_basics.cpp

It prints v = [1.5708 0 0] and q_recovered = [1 0 0] up to rounding. The direction of \(v\) is the initial heading of the great circle from the pole to the equator, and its norm, \(\pi/2\), is the distance between them. On Euclidean space, the two maps are addition and subtraction.

euclidean = geodex.Euclidean(3)

p = np.array([1.0, 0.0, 0.0])
q = np.array([0.0, 1.0, 0.0])

v = euclidean.log(p, q)
print("v =", v)  # [-1, 1, 0]
q2 = euclidean.exp(p, v)
print("q2 =", q2)  # [0, 1, 0], which is q

Full example: examples/tutorials/geodex_basics.py

std::cout << "q2 = " << q2.transpose().format(fmt)
          << "\n";  // [0, 1, 0], which is q

Full example: examples/tutorials/geodex_basics.cpp

It prints v = [-1 1 0] and q2 = [0 1 0].

Note

exp(p, log(p, q)) recovers \(q\) within the injectivity radius of \(p\), \(\pi\) on the sphere. Antipodal points lie at distance \(\pi\), where the geodesic is not unique, and log returns a zero vector with a warning.

4. Measure distances#

distance(p, q) is the length of the shortest path, the norm of \(\log_p(q)\). The north pole and a point on the equator are a quarter of a great circle apart.

sphere = geodex.Sphere()

p = np.array([0.0, 0.0, 1.0])  # north pole
q = np.array([1.0, 0.0, 0.0])  # equator

d = sphere.distance(p, q)
print("d =", d)  # 1.5708, about pi/2

Full example: examples/tutorials/geodex_basics.py

geodex::Sphere<> sphere;

Eigen::Vector3d p{0.0, 0.0, 1.0};  // north pole
Eigen::Vector3d q{1.0, 0.0, 0.0};  // equator

double d = sphere.distance(p, q);
std::cout << "d = " << d << "\n";  // 1.5708, about pi/2

Full example: examples/tutorials/geodex_basics.cpp

It prints d = 1.5707963267948966, \(\pi/2\). On Euclidean space, the distance is the norm of the difference.

euclidean = geodex.Euclidean(3)

p = np.array([1.0, 0.0, 0.0])
q = np.array([0.0, 1.0, 0.0])

d = euclidean.distance(p, q)
print("d =", d)  # 1.41421, about sqrt(2)

Full example: examples/tutorials/geodex_basics.py

It prints d = 1.4142135623730951, \(\sqrt{2}\). On a circle, the torus \(\mathbb{T}^1\), the angles 0.1 and 6.0 are 5.9 apart in coordinates, and the shortest path wraps through \(2\pi\).

Note

distance() uses the midpoint method, which evaluates the logarithm at the geodesic midpoint [1]. With the exact exponential and logarithmic maps, as on the round sphere, it gives the exact geodesic distance.

5. Interpolate along geodesics#

geodesic(p, q, t) is the point a fraction \(t\) of the way along the geodesic from \(p\) to \(q\), \(\exp_p(t \log_p(q))\). On the sphere, it traces an arc of a great circle.

sphere = geodex.Sphere()

p = np.array([0.0, 0.0, 1.0])  # north pole
q = np.array([1.0, 0.0, 0.0])  # equator

mid = sphere.geodesic(p, q, 0.5)
print("mid =", mid)  # about [0.707, 0, 0.707]

# Trace the whole geodesic
for i in range(11):
    t = i / 10.0
    pt = sphere.geodesic(p, q, t)
    print(f"t={t:.1f}: {pt}")

Full example: examples/tutorials/geodex_basics.py

geodex::Sphere<> sphere;

Eigen::Vector3d p{0.0, 0.0, 1.0};  // north pole
Eigen::Vector3d q{1.0, 0.0, 0.0};  // equator

          << "\n";  // about [0.707, 0, 0.707]

// Trace the whole geodesic
Eigen::Vector3d pt;
for (int i = 0; i <= 10; ++i) {

6. Sample random points#

random_point() samples a point uniformly over the manifold. The samples come from a low-discrepancy sequence (scrambled Halton), which covers the space evenly with few samples. The 2-sphere maps the unit square onto the sphere with the cylindrical equal-area map, the torus maps each coordinate onto \([0, 2\pi)\), and Euclidean space fills a box, \([-1, 1]\) per coordinate by default. set_sampling_bounds(lo, hi) resizes that box.

sphere = geodex.Sphere()
euclidean = geodex.Euclidean(3)
torus = geodex.Torus(2)

p1 = sphere.random_point()     # uniform on the sphere
p2 = euclidean.random_point()  # uniform in [-1, 1]^3
p3 = torus.random_point()      # uniform in [0, 2 pi)^2

Full example: examples/tutorials/geodex_basics.py

geodex::Sphere<> sphere;
geodex::Euclidean<3> euclidean;
geodex::Torus<2> torus;

auto p1 = sphere.random_point();     // uniform on the sphere
auto p2 = euclidean.random_point();  // uniform in [-1, 1]^3
auto p3 = torus.random_point();      // uniform in [0, 2 pi)^2

Full example: examples/tutorials/geodex_basics.cpp

geodex provides three samplers, ScrambledHaltonSampler (the default), HaltonSampler (a fixed deterministic sequence) and PseudoRandomSampler (independent mt19937 samples). In C++, the sampler is a template parameter, and in Python a constructor keyword together with set_sampler.

# sampler is "scrambled" (the default), "halton" or "random".
r3 = geodex.Euclidean(3, sampler="random")
r3.set_sampler("halton")                    # or switch after construction

Full example: examples/tutorials/geodex_basics.py

// Euclidean space with the pseudo-random sampler instead of the default
// scrambled Halton sequence.
geodex::Euclidean<3, geodex::EuclideanStandardMetric<3>,
                  geodex::PseudoRandomSampler>
    r3;

Full example: examples/tutorials/geodex_basics.cpp

seed on a manifold reseeds its sampler, and geodex.seed (geodex::set_default_seed in C++) reseeds the source of the samplers constructed afterwards.

geodex.seed(42)   # the shared source of default samplers
sphere.seed(42)   # or one manifold's own sampler

Full example: examples/tutorials/geodex_basics.py

sphere.seed(42);               // or one manifold's own sampler

Full example: examples/tutorials/geodex_basics.cpp

See Sampling on Manifolds for the samplers and the maps in detail.

7. Wrap angles on the torus#

The \(n\)-torus \(\mathbb{T}^n\) is the product of \(n\) circles, with points stored as angles in \([0, 2\pi)^n\). The logarithm takes the shortest signed difference of each angle, wrapped into \([-\pi, \pi)\), and the exponential adds the tangent and wraps the result back into \([0, 2\pi)\).

torus = geodex.Torus(2)

p = np.array([0.1, 0.2])
q = np.array([6.1, 0.5])

# log wraps to the shortest path
v = torus.log(p, q)
print("v =", v)  # about [-0.283, 0.3], the difference 6.0 wrapped by 2 pi

# exp follows the tangent vector and wraps back to [0, 2 pi)
q_recovered = torus.exp(p, v)
print("q_recovered =", q_recovered)  # about [6.1, 0.5]

Full example: examples/tutorials/geodex_basics.py

geodex::Torus<2> torus;

Eigen::Vector2d p{0.1, 0.2};
Eigen::Vector2d q{6.1, 0.5};

          << "\n";  // about [-0.283, 0.3]

Eigen::Vector2d q_recovered = torus.exp(p, v);
std::cout << "q_recovered = " << q_recovered.transpose().format(fmt)
          << "\n";  // about [6.1, 0.5]

It prints v = [-0.2832 0.3] and q_recovered = [6.1 0.5]. The first angle moves back across zero instead of forward by 6.0.

8. Rotate and move rigid bodies#

geodex provides four Lie groups. The rotation groups \(\mathrm{SO}(2)\) and \(\mathrm{SO}(3)\) rotate without translating, and the special Euclidean groups \(\mathrm{SE}(2)\) and \(\mathrm{SE}(3)\) add a translation to describe rigid-body poses. Their exp is the group exponential, and the group composition couples the coordinates.

\(\mathrm{SO}(2)\) is the circle group, one angle in \([-\pi, \pi)\), with a bi-invariant canonical metric. \(\mathrm{SO}(3)\) is the group of spatial rotations. A point is a unit quaternion \([x, y, z, w]\), a tangent vector is a body angular velocity, and geodesics are quaternion SLERP.

so3 = geodex.SO3()

q0 = so3.random_point()  # unit quaternion [x, y, z, w]
q1 = so3.random_point()

w = so3.log(q0, q1)              # body angular velocity, shape (3,)
mid = so3.geodesic(q0, q1, 0.5)  # SLERP midpoint

Full example: examples/tutorials/geodex_basics.py

geodex::SO3<> so3;

Eigen::Vector4d q0 = so3.random_point();  // unit quaternion [x, y, z, w]
Eigen::Vector4d q1 = so3.random_point();

Eigen::Vector3d w = so3.log(q0, q1);              // body angular velocity
Eigen::Vector4d mid = so3.geodesic(q0, q1, 0.5);  // SLERP midpoint

Full example: examples/tutorials/geodex_basics.cpp

An \(\mathrm{SE}(2)\) pose is \((x, y, \theta)\), and a tangent vector is a body-frame velocity \((v_x, v_y, \omega)\). The default metric is the left-invariant metric with weights \((w_x, w_y, w_\theta)\),

\[\langle u, v \rangle = w_x u_x v_x + w_y u_y v_y + w_\theta u_\theta v_\theta ,\]

with unit weights by default.

se2 = geodex.SE2()

p = np.array([1.0, 2.0, 0.0])   # pose at (1, 2), heading east
q = np.array([3.0, 4.0, 1.57])  # pose at (3, 4), heading north

v = se2.log(p, q)
print("log:", v)

q_recovered = se2.exp(p, v)
print("recovered:", q_recovered)

d = se2.distance(p, q)
print("distance:", d)

Full example: examples/tutorials/geodex_basics.py

geodex::SE2<> se2;

Eigen::Vector3d p{1.0, 2.0, 0.0};   // pose at (1, 2), heading east
Eigen::Vector3d q{3.0, 4.0, 1.57};  // pose at (3, 4), heading north
Eigen::IOFormat fmt(4, Eigen::DontAlignCols, ", ", ", ", "", "", "[", "]");

std::cout << "log: " << v.transpose().format(fmt) << "\n";

std::cout << "recovered: " << q_recovered.transpose().format(fmt) << "\n";

It prints the logarithm, the pose it recovers, [3 4 1.57], and distance: 3.5117456798791093. A large sideways weight \(w_y\) makes sideways motion expensive, as for a wheeled base that drives only forward and backward.

p = np.array([0.0, 0.0, 0.0])  # facing east
q = np.array([2.0, 2.0, 0.0])  # same heading, offset diagonally

print("distance:", d)

Full example: examples/tutorials/geodex_basics.cpp

It prints distance: 20.09975124224178. The weight multiplies the squared sideways speed, and with \(w_y = 100\), a sideways displacement is ten times as long as the same displacement forward. A shortest path between two poses turns and drives instead of sliding, and it may reverse, as the Reeds-Shepp paths of a car do [1][2].

random_point() on \(\mathrm{SE}(2)\) samples the position uniformly within the sampling bounds (default \([0, 10]^2\)) and the heading uniformly from \([-\pi, \pi)\).

An \(\mathrm{SE}(3)\) pose is a translation followed by a scalar-last unit quaternion, \([t_x, t_y, t_z, q_x, q_y, q_z, q_w]\), and a tangent vector is a body twist \([v;\, \omega]\). geodesic follows the screw motion of the constant twist between two poses.

se3 = geodex.SE3()

a = se3.random_point()  # pose [tx, ty, tz, qx, qy, qz, qw], shape (7,)
b = se3.random_point()

xi = se3.log(a, b)             # twist [v; w], shape (6,)
mid = se3.geodesic(a, b, 0.5)  # screw-motion midpoint

Full example: examples/tutorials/geodex_basics.py

geodex::SE3<> se3;

Eigen::Matrix<double, 7, 1> a = se3.random_point();  // pose [t; q]
Eigen::Matrix<double, 7, 1> b = se3.random_point();

Eigen::Matrix<double, 6, 1> xi = se3.log(a, b);  // twist [v; w]
Eigen::Matrix<double, 7, 1> mid =
    se3.geodesic(a, b, 0.5);  // screw-motion midpoint

Full example: examples/tutorials/geodex_basics.cpp

Body and world frames#

A rigid-body velocity can be written in two frames. For a trajectory \(X(t)\) on a Lie group, the body velocity is \(X^{-1}\dot X\) and the spatial velocity is \(\dot X X^{-1}\). Inner products of body velocities give a left-invariant metric, unchanged by a change of the world frame, and inner products of spatial velocities give a right-invariant metric, unchanged by a change of the body frame [3].

The frame argument of \(\mathrm{SO}(3)\), \(\mathrm{SE}(2)\) and \(\mathrm{SE}(3)\) picks one. frame="body", the default, steps with \(\exp_p(\xi) = p \cdot \mathrm{Exp}(\xi)\), and frame="world" with \(\exp_p(\xi) = \mathrm{Exp}(\xi) \cdot p\). In C++, the choice is a retraction policy, SO3LeftExponentialMap or SO3RightExponentialMap, and the same pairs for \(\mathrm{SE}(2)\) and \(\mathrm{SE}(3)\).

The canonical metric of \(\mathrm{SO}(3)\) is bi-invariant [3], and both frames report the same distance between two rotations.

q0 = np.array([0.5, 0.0, 0.0, 0.8660])     # 60 degrees about x
q1 = np.array([0.0, 0.0, 0.7071, 0.7071])  # 90 degrees about z

# The metric is bi-invariant, and both frames report the same distance.
db = geodex.SO3(frame="body").distance(q0, q1)   # 1.8235
dw = geodex.SO3(frame="world").distance(q0, q1)  # 1.8235

Full example: examples/tutorials/geodex_basics.py

using BodySO3 =
    geodex::SO3<geodex::SO3CanonicalMetric, geodex::SO3LeftExponentialMap>;
using WorldSO3 =
    geodex::SO3<geodex::SO3CanonicalMetric, geodex::SO3RightExponentialMap>;

Eigen::Vector4d q0{0.5, 0.0, 0.0, 0.8660};     // 60 degrees about x
Eigen::Vector4d q1{0.0, 0.0, 0.7071, 0.7071};  // 90 degrees about z

// The metric is bi-invariant, and both frames report the same distance.
double db = BodySO3{}.distance(q0, q1);   // 1.8235
double dw = WorldSO3{}.distance(q0, q1);  // 1.8235

Full example: examples/tutorials/geodex_basics.cpp

\(\mathrm{SE}(3)\) does not have a bi-invariant metric [3], and the two frames report different distances between the same poses. \(\mathrm{SE}(2)\) does not have one either.

a = np.array([1.0, 0.0, 0.0, 0.5, 0.0, 0.0, 0.8660])  # pose [t; q]
b = np.array([0.0, 1.0, 2.0, 0.0, 0.0, 0.7071, 0.7071])

# SE(3) does not have a bi-invariant metric, and the frames report different
# distances.
db = geodex.SE3(frame="body").distance(a, b)   # 3.2424
dw = geodex.SE3(frame="world").distance(a, b)  # 2.8023

Full example: examples/tutorials/geodex_basics.py

using BodySE3 =
    geodex::SE3<geodex::SE3InvariantMetric, geodex::SE3LeftExponentialMap>;
using WorldSE3 =
    geodex::SE3<geodex::SE3InvariantMetric, geodex::SE3RightExponentialMap>;

Eigen::Matrix<double, 7, 1> a, b;
a << 1.0, 0.0, 0.0, 0.5, 0.0, 0.0, 0.8660;  // pose [t; q]
b << 0.0, 1.0, 2.0, 0.0, 0.0, 0.7071, 0.7071;

// SE(3) does not have a bi-invariant metric, and the frames report different
// distances.

double dw = WorldSE3{}.distance(a, b);  // 2.8023

Full example: examples/tutorials/geodex_basics.cpp

9. Combine manifolds#

A product manifold joins several manifolds into one configuration space. Points and tangent vectors stack the blocks, exp, log and geodesic act block by block, and the distance is the L2 combination of the block distances. A point in space and a planar base pose, such as an end-effector position and the pose of a mobile base, form a point of \(\mathbb{R}^3 \times \mathrm{SE}(2)\).

space = geodex.Product([geodex.Euclidean(3), geodex.SE2()])
print("dim =", space.dim())  # 6

c = space.random_point()  # one joint low-discrepancy sample over both blocks

Full example: examples/tutorials/geodex_basics.py

auto space = geodex::make_product(geodex::Euclidean<3>{}, geodex::SE2<>{});
std::cout << "dim = " << space.dim() << "\n";  // 6

auto c =
    space.random_point();  // one joint low-discrepancy sample over both blocks

Full example: examples/tutorials/geodex_basics.cpp

It prints dim = 6. The product samples from one low-discrepancy sequence over the combined coordinates (see Sampling on Manifolds).

10. Change the metric#

ConstantSPDMetric defines a point-independent inner product from a symmetric positive definite matrix \(A\),

\[\langle u, v \rangle = u^\top A\, v .\]

With \(A = \mathrm{diag}(4, 1, 1)\), a unit step along the first coordinate has length \(\sqrt{4} = 2\), twice the length of a unit step along the others. In Python, ConfigurationSpace(base, metric) puts a metric on a base manifold. In C++, the metric is a template parameter, as in Euclidean<3, ConstantSPDMetric<3>>.

A = np.diag([4.0, 1.0, 1.0])
weighted = geodex.ConstantSPDMetric(A)

r3_weighted = geodex.ConfigurationSpace(geodex.Euclidean(3), weighted)

p = np.array([0.0, 0.0, 0.0])
u = np.array([1.0, 0.0, 0.0])
v = np.array([0.0, 1.0, 0.0])

ip = r3_weighted.inner(p, u, v)  # 0.0, still orthogonal
n = r3_weighted.norm(p, u)       # 2.0, scaled by sqrt(4)

q = np.array([1.0, 1.0, 1.0])
d = r3_weighted.distance(p, q)
print("d =", d)  # sqrt(4 + 1 + 1) = sqrt(6), about 2.449

Full example: examples/tutorials/geodex_basics.py

Eigen::Matrix3d A = Eigen::Vector3d(4.0, 1.0, 1.0).asDiagonal();
geodex::ConstantSPDMetric<3> weighted{A};

geodex::Euclidean<3, geodex::ConstantSPDMetric<3>> r3_weighted{weighted};

Eigen::Vector3d p{0.0, 0.0, 0.0};
Eigen::Vector3d u{1.0, 0.0, 0.0};
Eigen::Vector3d v{0.0, 1.0, 0.0};

double ip = r3_weighted.inner(p, u, v);  // 0.0, still orthogonal
double n = r3_weighted.norm(p, u);       // 2.0, scaled by sqrt(4)

Eigen::Vector3d q{1.0, 1.0, 1.0};
double d = r3_weighted.distance(p, q);
std::cout << "d = " << d << "\n";  // sqrt(4 + 1 + 1) = sqrt(6), about 2.449

Full example: examples/tutorials/geodex_basics.cpp

It prints d = 2.449489742783178, \(\sqrt{6}\), against \(\sqrt{3}\) under the standard metric. The same metric works on any manifold with 3-vector tangents, the sphere among them.

p = np.array([0.0, 0.0, 1.0])
u = np.array([1.0, 0.0, 0.0])

print("n =", n)  # 2.0, the same weighting

Full example: examples/tutorials/geodex_basics.py

11. Try it: swap the retraction#

A retraction is a cheaper map that agrees with the exponential map near the base point. On the sphere, the projection retraction normalizes \(p + v\) instead of following a great circle. It agrees with the exponential map to second order in \(\|v\|\) and does not evaluate trigonometric functions.

sphere = geodex.Sphere(retraction="projection")

p = np.array([0.0, 0.0, 1.0])
q = np.array([1.0, 0.0, 0.0])

# log and exp under the projection retraction give an approximate round trip
v = sphere.log(p, q)
q_approx = sphere.exp(p, v)
print("q_approx =", q_approx)

Full example: examples/tutorials/geodex_basics.py

using ProjectionSphere = geodex::Sphere<2, geodex::SphereRoundMetric,
                                        geodex::SphereProjectionRetraction>;
ProjectionSphere sphere;

Eigen::Vector3d p{0.0, 0.0, 1.0};
Eigen::Vector3d q{1.0, 0.0, 0.0};
Eigen::IOFormat fmt(4, Eigen::DontAlignCols, ", ", ", ", "", "", "[", "]");

// log and exp under the projection retraction give an approximate round trip
Eigen::Vector3d v = sphere.log(p, q);
Eigen::Vector3d q_approx = sphere.exp(p, v);
std::cout << "q_approx = " << q_approx.transpose().format(fmt) << "\n";

Full example: examples/tutorials/geodex_basics.cpp

It prints q_approx = [0.7071 0 0.7071]. The projection retraction reaches only the open hemisphere around \(p\), and a target 90 degrees away comes back at 45 degrees. Use it for short steps, and the exponential map for long ones. The metric stays the round metric.

\(\mathrm{SE}(2)\) also has a cheap Euler retraction.
