MoveIt 2 Planner#

geodex_moveit is a planner plugin for MoveIt 2. It plans joint paths for fixed-base arms under a Euclidean or a kinetic-energy metric. In this guide, an FR3 moves a box from the middle compartment of a shelf to the top compartment, and we plan the move under both metrics.

1. Build the plugin#

git clone https://github.com/utiasSTARS/geodex_moveit.git
cd geodex_moveit
pixi run -e jazzy build

See ROS 2 for the build in a colcon workspace.

2. Launch the demo#

The launch starts move_group with the geodex pipeline, the FR3 on mock hardware with the box in its gripper, the shelf, and RViz.

pixi shell -e jazzy
source install/jazzy/setup.bash
ros2 launch geodex_moveit_demos fr3_shelf.launch.py mock_hardware:=true rviz:=true

3. Plan and execute#

In a second shell of the same environment, plan the move under the kinetic-energy metric and execute it.

ros2 run geodex_moveit_demos fr3_shelf_plan.py

It prints the result, and RViz shows the motion of the video at the top.

kinetic_energy: planning_time=54 ms points=65 duration=3.186 s
54 ms

planning time

0.2 ms

The times are from an Intel Core i7-10875H. The script sets a seed and the iteration budget. Run it again and you get the same trajectory.

4. Try it: plan with the Euclidean metric#

ros2 run geodex_moveit_demos fr3_shelf_plan.py --metric euclidean

euclidean: planning_time=27 ms points=42 duration=2.047 s
27 ms

planning time

0.1 ms

first solution

1500

iterations

The Euclidean path is shorter in joint space, 2.45 rad against 5.18 rad, and turns joint 1 at the base by 1.53 rad. The kinetic-energy path turns joint 1 by 0.11 rad and moves the light wrist joints instead.

On a real FR3, the joints at the base stay almost still under the kinetic-energy metric, and they swing the arm under the Euclidean metric.

Switch the metric per robot#

robot names a geodex robot model, for example panda or fr3_arm_gripper, and metric selects euclidean or kinetic_energy for it. With robot empty, set checker: moveit. The plugin then plans under the Euclidean metric for any group of revolute and prismatic joints. The FR3 of the demo sets these parameters.

geodex_moveit_demos/config/fr3_shelf_geodex.yaml#
robot: fr3_arm_gripper
end_effector_link: 2f85_tcp
planner:
  collision_check_resolution: 0.002
smoothing:
  time_fraction: 0.1
obstacle_padding: 0.000404
totg:
  path_tolerance: 0.0001
  resample_dt: 0.05
  min_angle_change: 0.001

The plugin supports only fixed-base arms at the moment. Plan a mobile manipulator with geodex directly, as in Whole-Body Planning.

Attached objects#

The plugin plans with every object attached in the planning scene. end_effector_link names the link that the objects attach to. The vamp checker models an attached object in one of two ways.

The demo’s 0.04 x 0.24 x 0.16 m box in its enclosing sphere (left) and in a cover of 16 spheres (right).

The checker encloses the attached shapes in one sphere. This is the default and does not need a parameter. Use it for a compact object, or where the motion leaves room around the object, as in the demo.

end_effector_link: 2f85_tcp

attached_object.spheres lists x, y, z and radius per sphere in the frame of the link that holds the object. Use a cover where the object passes close to obstacles.

end_effector_link: 2f85_tcp
attached_object:
  spheres: [
      -0.000002, -0.100003, -0.002372, 0.036221, -0.000002, -0.100001, 0.106248, 0.040332,
      ...]
attachment_padding: 0.0012

foam fits the spheres to a mesh of the object, and attached_object_spheres.py of geodex_moveit_demos prints this block from foam’s output.

Collision checking#

checker: vamp checks geodex’s sphere model of the robot against the obstacles of the planning scene. checker: moveit uses the planning scene’s own collision checking, for any robot. obstacle_padding is the clearance that planned configurations keep from every obstacle. Raise it when MoveIt’s ValidateSolution rejects a trajectory.

Parameters#

General#

Parameter

Type

Default

Range

Description

robot

string

empty

Name of the geodex robot model that sets the mass matrix, the heuristic and the collision model, or empty to plan in a Euclidean space of the group’s dimension with the moveit checker.

metric

string

euclidean

euclidean, kinetic_energy

Riemannian metric on the configuration space, where kinetic_energy requires a robot model.

checker

string

vamp

vamp, moveit

Collision checker, either vamp for geodex’s sphere model of the robot, which requires a robot model, or moveit for the planning scene.

base_link

string

empty

Root link of the vamp collision model, or empty for the model frame.

end_effector_link

string

empty

MoveIt link in which the vamp checker expresses attached-object spheres, or empty for the collision model’s own end-effector frame.

end_effector_offset

double array

empty

fewer than 7 entries

Pose of the collision model’s end-effector frame in end_effector_link as x, y, z, roll, pitch, yaw, required when end_effector_link is another link, for example [0, 0, 0.105, 0, 0, 0] for the Panda’s panda_grasptarget in panda_hand.

attachment_padding

double

0.0

≥ 0.0

Meters added to every attached-object sphere radius during planning.

obstacle_padding

double

4.3e-06

≥ 0.0

Clearance in meters that planned configurations keep from every obstacle of the planning scene.

exact_attached_box

bool

true

Also check an attached box exactly against the world’s boxes, when an attached box primitive or attached_object.box_size gives one.

exact_attached_box_margin

double

0.001

≥ 0.0

Meters added to each half extent of the attached box in the exact test.

ignore_unsupported_shapes

bool

false

Leave out scene shapes that the vamp checker cannot represent, such as planes and octrees, instead of failing the request.

Default

Link in whose frame box_size, box_pose and spheres are given, or empty for the link the body is attached to.

double array

Attached box size along x, y and z in meters, or empty to take the largest box primitive of the attached bodies.

double array

empty

Attached box center as x, y, z, roll, pitch, yaw in the frame of attached_object.link, or empty for the link origin.

double array

empty

Spheres of the attached object for the vamp checker as x, y, z and radius per sphere in the frame of attached_object.link, for example generated by foam. Empty takes the sphere primitives of each attached body, or one sphere that encloses a body without them.
Planner#

Parameter

Type

Default

Range

Description

planner.config.grrtstar.range

double

1.2

> 0.0

Maximum extension length in metric units.

planner.config.grrtstar.greedy_biasing_ratio

double

0.9

0.0 to 1.0

Probability per sample that the informed sampler narrows its cost bound to the greedy cost.

planner.config.grrtstar.planner_greedy_biasing_ratio

double

0.0

0.0 to 1.0

G-RRT* planner-side greedy biasing ratio that chooses the cost bound passed to the sampler, where 0 leaves the narrowing to greedy_biasing_ratio.

planner.config.grrtstar.rewire_factor

double

1.1

> 0.0

Scale on OMPL’s k-nearest rewiring constant.

planner.config.grrtstar.max_neighbors

int

0

≥ 0

Maximum size of the k-nearest rewiring neighborhood, or 0 to leave it uncapped.

planner.config.grrtstar.greedy_cost_for_tree_pruning

bool

true

Prune the trees with the greedy cost rather than the current solution cost when greedy_biasing_ratio or planner_greedy_biasing_ratio is positive.

planner.termination

string

anytime

first, anytime

Termination condition, where first stops at the first solution and anytime optimizes until the allowed planning time minus the share that smoothing.time_fraction reserves for smoothing.

planner.collision_check_resolution

double

0.01

> 0.0

Maximum joint-space distance between collision checks along an edge, in the norm of the group’s coordinates for every metric. The returned path is checked at this spacing. With a geodex collision model, the smoother spaces its checks by the sphere motion of this distance at the robot’s largest sphere speed.

planner.edge_motion_validator

bool

true

Check the search’s edges with the model’s VAMP edge check for a robot with a geodex collision model, and with the request’s validity checker at collision_check_resolution otherwise. When false, OMPL’s discrete motion validator checks the edges at the same resolution.

planner.ik_timeout

double

0.1

> 0.0

Longest time in seconds spent sampling joint goals for pose and position goals. The valid solution nearest the start becomes the goal.

planner.max_iterations

int

0

≥ 0

Search iteration budget in addition to the time budget, or 0 for the time budget alone.

planner.seed

int

-1

≥ -1

Seed of OMPL’s random number generator and geodex’s samplers for the search, or -1 to seed from the system.
Smoothing#

Parameter

Type

Default

Range

Description

smoothing.enabled

bool

true

Smooth the solution with geodex’s metric-aware smoother. It returns the first of its stages, from the smoothed path back to the planner’s path, that passes the planner’s validity checker, the joint bounds and the smoother’s edge checks.

smoothing.output_spacing

double

0.01

≥ 0.0

Longest joint-space step between the smoother’s returned waypoints, or 0 for no limit. The waypoints lie at equal steps between the corners the smoother keeps.

smoothing.round_corners

bool

true

Round the corners of the smoothed path into metric-aware, twice continuously differentiable curves, checked like every other edge.

smoothing.seed

int

42

≥ 0

Seed of the smoother’s random shortcuts.

smoothing.time_fraction

double

0.2

0.0 to 0.9

Share of allowed_planning_time that an anytime search leaves to smoothing.
